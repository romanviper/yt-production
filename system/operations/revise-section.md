# Operation — Revise Section

## Responsibility

Resolve only the user-approved change request.

For canonical direct-authorship work, preserve the same architecture as drafting: historical substrate is the primary model of history; evidence access is secondary verification. Do not repair a prose problem by returning to evidence-ledger exposition.

The packet contains current prose, the approved change request, compact section boundary, Historical Substrate and a hash-bound diagnosis projection with the review verdict, Issues and Routing only. The review diagnosis and user request must identify the observable target, bounded change and pass condition. If the combined authority does not, report a blocker instead of reconstructing omitted context.

This task is the section's single diagnosed revision pass. Do not open another polish loop or broaden the issue set.

Preserve successful creative choices. Use the smallest change that passes the stated acceptance test, unless the approved request explicitly routes the issue back from local prose and permits a full section rewrite.

The Historical Substrate boundary, evidence ceiling, act role, entry/exit state and continuity remain fixed. If the requested fix actually belongs to product architecture, Historical Substrate or missing evidence, report that blocker instead of compensating with prose.

If evidence verification is needed, use the bounded broker only for the chosen revision. Do not survey the ledger to invent a new telling.

Update the handoff only when the achieved exit state or continuity facts changed. Record issue IDs and observable results in the revision log; do not describe generic polishing.
